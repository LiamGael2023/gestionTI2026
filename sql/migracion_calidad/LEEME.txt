# Migracion Calidad -> hidrologia (BDG_SGDA, PostgreSQL 16 local)

Fecha: 2026-08-24. Base LOCAL: localhost:5432, BDG_SGDA (NO tocar 10.0.100.81).

## Que se hizo
1. Creo hidrologia.drenes_catastro (31 puntos, IDs DREN-001..031) y
   hidrologia.calidad_catastro (13 puntos, IDs CAL-001..013).
   Identidad = ubicacion + cooreste + coornorte, desde TODAS las tablas base
   de calidadaguadrenada2022..2026 y calidadaguasuperficial2022..2026.
2. Columna `tipo` en pozos_monitoreo y calidad_agua_laboratorio:
   - filas existentes (pozos) -> 'comportamiento freatico' (10626 / 2936)
   - mediciones de drenes -> 'drene' (143)
   - mediciones de calidad (rios/canales) -> 'calidad agua' (126)
3. Columnas de enlace id_dren / id_calidad (FK a los catalogos) en ambas tablas,
   porque id_pozo solo acepta pozos_catastro (FK existente, se respeta).
4. Migro 269 mediciones (2022-2026):
   - pozos_monitoreo: in-situ ce, ph, std, t + campana (ej. 'ABRIL 2022') + observaciones
   - calidad_agua_laboratorio: parametros extendidos (nitratos, sulfatos, durezatotal,
     calcio, coliformes...) enlazados por id_medicion + fecha_toma_muestra + orden
   Los schemas originales de calidad NO se modificaron (solo lectura).

## Totales finales
drenes_catastro=31 | calidad_catastro=13 | pozos_monitoreo=10895 | calidad_agua_laboratorio=3205

## Mapeo de columnas clave (origen -> hidrologia)
- dureza (drenes 2022-23) -> durezatotal
- observacion (2022-24) / observaciones (2025-26) -> observaciones
- mes/mes_campana/monitoreo -> campana computada ('MES AAAA' desde fechamonitoreo)
- ce/ph/std/t -> pozos_monitoreo (in-situ); resto parametros -> calidad_agua_laboratorio
- fechamonitoreo era VARCHAR en superficial 2023 -> normalizado a DATE
- filas "basura" (todo NULL, p.ej. ids 10/11 de sup2025) fueron excluidas
